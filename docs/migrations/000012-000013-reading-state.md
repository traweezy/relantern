# Reading-state migrations 000012 through 000015

## Scope

Migration `000012_reading_state.sql` adds the published story summary view,
owner state, tags, item-tag links, revision-bound annotations, explicit
feedback, and the mutation log. Migration `000013_feedback_mutation_links.sql`
links feedback to the exact command so Undo can reverse every command side
effect. Migration `000014_reading_state_integrity.sql` enforces owner-scoped
tag references, feedback idempotency, and the required collection index.
Migration `000015_story_primary_source.sql` adds the ordered primary evidence
URL used by both the visible source action and the `V` shortcut.

Both migrations are additive. Existing published stories project as unread
Inbox entries without an eager backfill. No live provider, delivery service, or
public route is enabled.

## Forward rollout

1. Apply all four migrations before deploying API or web code.
2. Verify the view resolves the latest completed/reviewable brief and an
   HTTPS primary source URL.
3. Run the reading-state integration test against the migrated database.
4. Deploy the private API, then web, and verify optimistic conflict plus Undo.
5. Observe state-command error rate, latency, and database lock waits.

## Rollback

Production rollback is application-first and forward-only: disable the new web
and API routes, retain schema and mutation history, and deploy a correcting
forward migration. Do not run Goose `down` in a hosted environment.

The development-only down blocks must run in descending order from `000015`.
They are for disposable local verification only. Rolling below `000012`
destroys reading state, tags, annotations, feedback, and mutation history.

## Variables and permissions

No new environment variable or external permission is introduced. Existing
web-to-API service authentication and the application database role cover the
new private operations.
