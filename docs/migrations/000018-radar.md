# Technology Radar migration 000018

## Scope

Migration `000018_radar.sql` additively introduces the private package-evidence
and decision ledger:

- `app.radar_discovery_runs` records idempotent owner and scheduled evidence
  passes and their River job identity.
- `app.package_candidate_evidence` is the bounded inbox for already-ingested,
  attributable package observations. The migration does not add a network
  collector or enable a provider.
- `app.package_candidates` holds the owner-scoped current state, incumbent,
  review date, and optimistic version.
- `app.package_metrics` preserves immutable metric snapshots instead of
  replacing history.
- `app.radar_comparisons` requires exactly seven comparison dimensions and
  retains the evidence links used by each assessment.
- `app.radar_decisions` preserves system assessments and explicit owner
  decisions with project applicability, compatibility requirements, and exit
  conditions.

Database checks enforce bounded data shapes and prevent `decision_source =
'system'` from entering `Adopt`. The worker classifier can only suggest
`Assess`, `Hold`, or `Reject`; `Trial` and `Adopt` remain owner-only choices.

## Forward rollout

1. Apply migration 18 before starting the updated API or worker.
2. Deploy the private API and worker before the web application.
3. Run `make test-integration`. Confirm the Radar integration test creates one
   River job across an idempotent replay, processes credible and misleading
   evidence, and rejects a direct system-originated Adopt insert.
4. In a hosted environment, open `/radar` as the owner and confirm an empty
   ledger renders without a fixture or stale-data fallback. The local/test-only
   seed adds three synthetic inbox records for disconnected workflow testing.
5. Insert hosted evidence only through a separately approved ingestion
   adapter. The default local stack has no live npm, GitHub, OpenAI, or deps.dev
   Radar connection.
6. Observe maintenance queue depth, job age, API error rate, run duration,
   processed evidence count, misleading count, and overdue review count.

## Rollback

Hosted rollback is application-first and forward-only. Roll back web, API, and
worker code while retaining migration 18 and all evidence, metric, comparison,
and decision history. Correct a schema defect with a new additive migration.

The Goose `down` block is for disposable local databases only. Never use it in
staging or production because it deletes the complete Radar decision ledger.

## Variables and permissions

No variable, secret, egress permission, hosted service, or public route is
added. Radar reuses the private web-to-API credential, the existing PostgreSQL
role, and the maintenance River queue. Only the authenticated web application
can request a run or record an owner decision.
