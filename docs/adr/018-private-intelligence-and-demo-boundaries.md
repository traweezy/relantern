# ADR 018: Private intelligence reads and isolated demonstration

Status: accepted on 2026-08-29.

## Context

PR 12 introduces the first product-facing Today, Live, and Story reads. The
browser must not receive a database credential or the web-to-API service token.
The anonymous demonstration must remain usable with every private dependency
offline and must not become an anonymous application API.

Next.js nonce-based Content Security Policy also requires request rendering.
Prerendered HTML cannot receive the unique nonce generated by Proxy for a
request, and executable scripts without that nonce do not hydrate.

## Decision

- The Go API owns read models over application intelligence tables.
- `/api/v1/today`, `/api/v1/live`, and `/api/v1/stories/{storyId}` require the
  existing private bearer credential. Comparison uses constant time, failures
  return bounded Problem Details, and the token is never logged or returned.
- Authenticated Server Components call the private API with a five-second
  timeout, no shared cache, a two-million-character response limit, and runtime
  validation before rendering.
- The browser Live connection terminates at an authenticated Next.js SSE route.
  That route polls the bounded seven-day private snapshot once per second. A
  reconnect replays stable event IDs, and the client deduplicates up to the
  shared 200-row virtualization threshold. Durable outbox cursors remain a
  later transport hardening step and are not claimed by this slice.
- `/demo` and its allowlisted story route import a deeply frozen synthetic
  snapshot directly. Demo state uses only namespaced `sessionStorage` and can be
  reset. It makes no auth, API, SSE, database, object-storage, delivery, or
  provider request.
- Every application document, including `/demo`, remains request-rendered so
  every executable script receives the request CSP nonce. "Static demo" means
  immutable fixture data and a static dependency boundary, not static HTML.

## Reliability and performance objectives

- Private API read p95 remains below 300 milliseconds on production-like data.
- Live publication is visible within two seconds while the connection is open.
- The BFF aborts an unresponsive API read after five seconds and renders a
  fail-closed degraded state instead of fixture or stale private data.
- Today and demo initial JavaScript stay below the shared 220 KiB and 180 KiB
  gzip budgets respectively. Lists stop accumulating at 200 items until the
  virtualized collection slice lands.
- Existing API access logs cover every read. Internal store failures add a
  structured operation-specific error without payload or credential data.

## Security and rollback

Only `web` receives public hosted traffic. The API remains private even though
it independently authenticates every intelligence read. Source URLs are
validated before rendering and open in isolated browsing contexts.

Rollback removes the three API operations and their server-only client. The
database schema is unchanged, so no migration or data rollback is required.
The demo snapshot can remain available independently.

## Consequences

Request rendering deliberately gives up shared HTML caching for strict nonce
CSP. The demo still has no request-time database, model, auth, or private API
dependency. Byte-equivalent responses are not expected because nonces differ;
session-independent semantic content is the acceptance condition.
